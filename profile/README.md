<p>问「多少钱一条」几乎问不出有用答案，因为不同服务商的计价单位根本不是一回事：有的按并发、有的按流量、有的按账号数。这篇按参数说明书的写法，把影响价格的参数一项一项列清楚，给出常见取值和折算方法，再说清「独立出口、独立会话」这两个词在参数上到底对应什么。看完你至少能拿两份报价单做出同口径比较，价格区间仅供参考。</p>

<h2>一、先分清计价单位，价格才有可比性</h2>
<p>两份报价单看起来单价差三倍，很多时候不是贵和便宜，而是量的口径不同。先把单位统一，再看绝对值。统一的方法只有一个：折算成「每个账号每 30 天、每天在线 8 小时」的支出，再横向比。</p>

<h3>三种常见计价口径</h3>
<p>一是按并发线数计费，一条线同时只允许一个会话，价格最直观；二是按流量计费，按 GB 结算，适合轻量操作；三是按账号或环境数计费，把出口、会话、指纹打包成一份。前两种看用量，第三种看座席，团队规模不同，划算的那一档会变。</p>

<h3>折成单号成本的算法</h3>
<p>按线计费：月单价除以同时在线账号数。按流量：月消耗 GB 乘以单价，再除以账号数。按账号计费：直接是单号价，但要注意是否含备用线。一次折算就能看出，同样标称一百多块的方案，实际单号成本可能相差两倍以上。</p>

<p>三类最容易踩：指定城市、IP 段干净度承诺、备用线。指定城市属于资源稀缺，加价合理；干净度承诺要看是否有可验证的指标，只写「高纯净」不算承诺；备用线按量计费时通常只在启用期间收费，包月方案往往要整月付费，选之前问清楚。</p>

<h2>三、隔离参数：出口独占与会话独占</h2>
<p>「一号一环境」在参数上拆成两件事：出口独占和会话独占。只做前者，多个号还是可能在同一个指纹下运行；只做后者，多个号还是共用一条线。两个参数都到位，多人并行才谈得上互不牵连。</p>
<h3>出口独占的三种形态</h3>
<p>整条独享，一条线只给一个号，最贵也最省心；按端口分配，一条线切成几个端口，各端口独立出口 IP，性价比高，但要注意出口是否真的不同；按时段独占，白天给一个人晚上给另一个人，价格最低，问题是切换时段的瞬间容易出现归属地跳变。</p>
<h3>会话独占不只是不共用 Cookie</h3>
<p>会话包含登录态、本地存储、缓存、指纹参数四部分。常见做法是每个号一个 profile 目录，但很多人忽略了网络层的会话：同一个浏览器实例走同一出口，两个标签页分别登两个号，出口其实还是共用的。参数上要确认「每号独立出口」，而不是「每号独立标签」。</p>

<h2>四、多人并行时的参数换算</h2>
<p>三到五个人共用一个后台，最常犯的错是按人数买线，而应该按「同时在线会话数」买。一个人上午用、另一个人下午用，可以共用一条线；但共用的前提是时段完全不重叠，且两边环境参数一致，否则同一账号在不同指纹下切换，反而更奇怪。</p>
<h3>并发与账号数的经验比例</h3>
<p>轻度使用，五个人配三条线够用，靠错峰；中度使用，五个人配五条线；重度使用，比如跑批量任务或长会话，一个人可能同时占用两条。判断方法很简单，看后台的并发峰值，取最近七天峰值的 1.2 倍，就是该买的线数，留一点余量比频繁扩容便宜。</p>
<h3>一条线能不能给同一个人的两个号用</h3>
<p>技术上可以，风险上不建议。两个号共用出口，在平台侧看就是同一处网络下的两个账号，等于自己把两个号绑在一起。价格上省一条线的钱，代价可能是两个号一起受影响，这笔账不划算。</p>

<h2>常见问答</h2>
<h3>报价单上写「高纯净住宅」，这个能当参数看吗？</h3>
<p>答：不能直接当。纯净度要看可验证的口径，比如是否承诺同一 IP 近 30 天内绑定过的账号数上限，或者是否提供换线次数。只有形容词没有指标的，按普通共享线预期即可。</p>

<h3>按流量计费是不是一定更便宜？</h3>
<p>答：看业务类型。纯文字对话、轻量接口调用，流量很小，按流量通常更省；视频、大文件、长时间挂机会话，流量涨得快，按线计费更可控。先测一周实际流量再决定。</p>

<h3>指定城市和指定国家，差价值不值？</h3>
<p>答：看账号类型。资料填了具体城市的账号，指定城市一致性更好；只填了国家的账号，指定国家通常够用。差价常在 10% 至 25%，按账号重要性分别对待，不必全都上城市级。</p>

<h3>备用线到底要不要买？</h3>
<p>答：看能不能接受中断。日常对话断几分钟影响不大，可以只在关键时段开备用；跑长任务或对外服务，备用线的钱值得花，一次中断的损失往往超过一个月差价。</p>
